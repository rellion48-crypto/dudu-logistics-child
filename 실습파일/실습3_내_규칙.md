# 실습 3 - 처리 방침 (이름: 이영민)

> 오늘의 핵심입니다. **정답이 없습니다.** 같은 데이터를 봐도 무엇을 먼저 막을지는 사람마다 다릅니다.

## 내가 정한 규칙

실습 2에서 고른 것 중 **몇 개만** 고릅니다. 다섯 개가 목표지만 한 개여도 됩니다.

각 줄이 **내일 만들 기능 하나와 짝지어져야** 합니다. 짝이 안 지어지면 아직 규칙이 아니라 관찰입니다.

| # | 조사에서 본 것 | 내가 정한 방침 | 그래서 내일 만들 기능 |
|---|---|---|---|
| 1 | 요금이 비어 있거나 부피무게가 미반영된 건이 있음 | 실측무게와 부피무게 중 큰 값을 요금무게로 산정하여 자동으로 정규 요금 계산 | 가로, 세로, 높이, 무게 입력 시 요금 자동 계산 |
| 2 | 지역 이름(SEOUL, 서울시, 서울특별시 등)이 25가지로 섞여 있음 | 자유 입력을 막고 표준 광역시/도 18개 선택지로만 고르도록 제한 | 도착 지역 드롭다운 선택 폼 구현 |
| 3 | 무게가 0 이하이거나 세 변의 합이 160cm/25kg을 초과하는 건이 있음 | 접수 범위를 초과하면 접수를 차단하고 사유 표시 | 무게 0 이하 및 크기 초과 접수 차단 validation |
| 4 | 배송 완료 상태인데 완료 시각이 누락되거나 접수일시보다 빠름 | 배송 추적 이벤트(tracking_events)와 연동하여 완료 시각 자동 채움 | 배송추적 상태-시각 자동 동기화 기능 |
| 5 | 금지 품목(현금, 부탄가스, 보조배터리 등)이 입력되는 경우가 있음 | 금지 품목 키워드 검수 후 접수 불허 | 물품명 입력 시 금지 품목 실시간 검증 기능 |
